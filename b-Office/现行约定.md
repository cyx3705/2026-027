# HistoryPortunus 现行约定

本仓唯一的长期文档。这里只写**从代码和测试里看不出来的项目元数据**；做法以代码为准，
每版做了什么看 `git log`。条目被推翻就直接改掉，不留历史。

## 取舍

- **它是别的模块的 AI 面，不是别的模块该调用的东西。** `portunus.*` 全部带 `HiddenReason`，不进 MCP，也不能经 `--runtime` 执行。要 MCP 地址就执行 `portunus.mcp.status` 读 Data，或订阅 `portunus.mcp.changed`。不要读 Cursor 的 `mcp.json`，也不要读 `endpoint.json` 来找 MCP。
- **MCP 投影按代码，不按那句已经删掉的简化。** 默认 `mcp.policy=standard` 时，非只读指令也会投影。硬排除的是：有 `HiddenReason` 的、`portunus.mcp.*`、`vulcan.mcp.*`、`vulcan.module.*`、`vulcan.app.quit`、`vulcan.app.close`，以及 `module.manifest.json` 里 `mcpExposure=hidden` 的模块的全部指令。`Level=Ask` 默认不出现在 tools/list；只有 `mcp.confirm=host` 且策略仍是 standard 时才列出。`readonly` 策略只留 `Readonly==true` 的，外加三条目录指令 `vulcan.command.list` / `show` / `domains`。工具名是指令名里每个非字母数字换成 `_`（`minerva.plan.package` → `minerva_plan_package`）。参数的 `Description` 进 JSON Schema，是 AI 唯一能读到的说明。拿不准时跑 `portunus.mcp.schema name=<指令名>`。
- **`mcp.surface` 只改 tools/list 的列法，不改谁能调什么。** `full`（缺省）是每条指令一个工具。`compact` 只列 `portunus_find`（按关键词返回匹配指令的说明与 Schema）和 `portunus_call`（`name` 加 `arguments` 执行一条），这样客户端常驻上下文与指令总数无关，适合不支持工具延迟加载的客户端。两个元工具在两种列法下都受理。`call` 拆出内层指令后，走和直调完全相同的策略、确认与留痕，不准嵌套。客户端只在握手时拉 tools/list，改了要重连才生效。
- **`mcp.confirm=host` 今天不会真的弹框。** 远端确认通道一律拒绝。危险指令被拒时不要提示别人去开这个开关。接通与否另议，不在改文档时改安全语义。
- **`mcp.policy` / `mcp.confirm` / `mcp.surface` 只在本模块设置库。** 数据目录 `state\portunus-settings.json`，唯一写口是 `portunus.mcp.config`（写入要确认，省略 value 只查看）。宿主 `vulcan.app.set` 写的是另一份文件，本模块不读。
- **`portunus.mcp.status` 的 Data 字段只增不减：** `running`、`port`、`url`、`policy`、`surface`。未监听时 `running=false`、`port=0`、`url=null`。事件 `portunus.mcp.changed` 的载荷是 `running`、`port`、`url`，没有 `policy`。
- **Web 是同机前端的航线，不是 MCP。** 客户端每次调用前重读数据目录下的 `endpoint.json`，字段 `port`、`serverId`、`processId`、`accessToken`，只增不减。请求必须同时带 `Authorization: Bearer <accessToken>` 与 `X-HistoryVulcan-Client: Shell`，缺一返回 401；可选 `X-Session-Id`、`X-Client-Name`。接口是 `GET /api/health`、`GET /api/commands`、`POST /api/command`（体 `{"text":"…"}`）。根路径 `/` 不是健康检查。令牌每次监听换发，热重载后旧令牌立即 401。
- **两条监听都只绑 127.0.0.1。** MCP 不校验 Bearer。启动成功后把用户级 `%USERPROFILE%\.cursor\mcp.json` 的 `history-vulcan` 写成 `url=http://127.0.0.1:<port>/mcp`，不写 Authorization。设置缺省 `mcp.autostart` / `web.autostart` 为 true，端口 `8777` / `8938`，重试次数 0：占用即失败，不改绑。别的模块不要写死这两个端口。
- **本机航线同一时刻只属于一个宿主进程。** 离线 CLI 与手册导出不开监听、不改 `endpoint.json`、不改 `mcp.json`。已有活进程占着航线时，后来的进程保持静默，不退到下一个端口。
- **设置、审计、日志与 endpoint 全在宿主给的数据目录** `ModuleData\HistoryPortunus`。不写包槽位，不读宿主数据根里留下的旧布局。

## 已知缺口

- 远端确认仍一律拒绝。`mcp.confirm=host` 只改变 tools/list 是否列出危险指令，执行时照旧拒绝。

## 工程约定

- 发版改三处版本号：`PortunusVersion.props` 的 `HistoryPortunusVersion`、`module.manifest.json`、`project.manifest.json`。最低宿主 HistoryVulcan 6.0.0。只引用已发布的 `HistoryVulcan.Core`，包内不带任何 `HistoryVulcan.*.dll`。
- 候选由 `vulcan.dev.submit` 构建并热装，本仓不自行发布。
- 自描述要照抄能跑：submit 前 `diana.docs.audit domain=portunus` 零缺陷。
- 不留 `history/`、方案、需求书。仍有效的结论写进本文、调用处注释或测试。

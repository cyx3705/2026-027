# 有效决策

- `DEC-PORT-001`：Portunus 1.0 只支持 HistoryVulcan 5.1+，不保留 5.0 兼容层。
- `DEC-PORT-002`：因 5.1 移除 MCP、client 与 schema 领域公开面，Portunus 在模块内维护传输专用实现，不将旧宿主 DLL 打入模块包。
- `DEC-PORT-003`：模块设置和审计保存在 `%AppData%\\HistoryVulcan\\state`，与运行时模块安装目录分离；模块不写入宿主包目录。（1.1.0 起由 DEC-PORT-005 取代落盘位置。）
- `DEC-PORT-004`：MCP 只服务本机回环。不校验 Bearer、不往 Cursor `mcp.json` 写鉴权头；启动成功后只写入 `url=http://127.0.0.1:<mcp.port>/mcp`。默认暴露策略为 `standard`。离线 CLI / 手册导出不得抢航线、不得删除活宿主的 `endpoint.json`。
- `DEC-PORT-005`（1.1.0，2026-10-01，宿主 6.0.0 统一契约 DEC-071）：只用 `IModuleContext` 上的窄接口。工具表读 `vulcan.command.list` 的 JSON 行、按 `vulcan.command.revision` 与 `vulcan.catalog.changed` 决定重拉，不再挂宿主注册表；确认与隐藏读目录行字段；运行方式读 `Environment.RunMode`，不再看进程参数 `--cli`；设置、治理、审计、日志与 `endpoint.json` 全在宿主给的数据目录 `ModuleData\\HistoryPortunus`。`portunus.mcp.status` 的 Data 给出 MCP 地址，供别的模块经总线读（Diana 不再读文件）。1.0.x 留在宿主数据根 `state\\` / `service\\` 的旧文件在宿主切换时一次性搬过来，模块不带认旧布局的代码。最低宿主 6.0.0。
- `DEC-PORT-006`（1.1.1，2026-10-01）：`mcp.policy` / `mcp.confirm` 只存在于 Portunus 自己的设置库（数据目录 `state\\portunus-settings.json`，即 `PortunusRuntime.Settings`），唯一写口是新增的 `portunus.mcp.config key=policy|confirm value=…`（级别「询问」，只查看时不问；与其余 `portunus.mcp.*` 一样对 MCP 硬排除）。宿主的 `vulcan.app.set` 写的是宿主 `service\\settings.json`，Portunus 从不读那里，此前 `portunus.mcp.status` 与网关拒绝文案里指向它的提示照做不生效，一律改指新指令。网关 tools/call 真正会走到的策略闸口在 readonly 拒绝时带上可执行提示；危险指令不提示 `confirm=host`，因为远端确认通道仍一律拒绝（`RefuseRemoteConfirmation`，接通与否另议）。审计脱敏里对不存在的 `vulcan.web.token` / `vulcan.mcp.token` 的特判删除，`vulcan.app.set` 的按键名脱敏保留。

- `DEC-PORT-007`（2026-10-02，宿主 6.1.0 DEC-072、Diana DEC-043）：消费文档退役。删除 `b-Office/package/模块API.md`（原文已落后：仍写 1.0.7 / 宿主 5.1.0）；指令表不再手写，读 `diana.docs.read domain=portunus`；自描述装不下的 MCP 投影规则与 Web 接口约定移入技术合同 REQ-PORT-006 / 007。manifest 去掉 `b-Office/package` 活动目录。本次只改文档，不发版。

# 技术合同

- `REQ-PORT-001`：模块必须仅引用 HistoryVulcan 5.1+ 的已发布 `host/` 快照，禁止跨仓 `ProjectReference` 与已删除的 Extensibility/MCP 程序集引用。
- `REQ-PORT-002`：所有 Web/MCP 操作必须经宿主总线调用权威命令；传输不得反射模块、维护第二份业务命令实现或绕过确认语义。
- `REQ-PORT-003`：Web 只接受回环、Shell 声明和本次监听凭据同时成立的请求。MCP 只绑定 127.0.0.1，不校验 Bearer，默认 `standard`；管理与模块生命周期命令不得投影为工具。启动成功后必须把 Cursor 用户级 `mcp.json` 的 `history-vulcan` 对齐到当前 url，且不得写入 Authorization。
- `REQ-PORT-004`：热重载时必须关闭 Web/MCP 监听器并撤销 endpoint 凭据，避免旧快照继续占用端口或持有命令总线。

- REQ-PORT-005：MCP JSON 参数转命令文本必须使用 CommandParser.QuoteArg；真实 Unicode、字面量反斜杠转义和控制字符逐字符保真，不在业务处理器猜测性解码。

- REQ-PORT-006（自原《模块API》移入，2026-10-02）：模块指令投影成 MCP 工具的规则。只有 `Readonly == true && HiddenReason == null` 的指令被投影；
  参数的 `ParameterSpec.Description` 进 JSON Schema，是 AI 唯一能读到的说明；工具名是指令名把 `.` 换成 `_`（`minerva.plan.package` → `minerva_plan_package`）；
  模块 `module.manifest.json` 的 `mcpExposure` 决定整体是否参与投影；拿不准时跑 `portunus.mcp.schema name=<指令名>`。
  `portunus.*` 本身全部声明 `HiddenReason`（防远程递归管理或关闭 MCP 服务），不投影、不能经 `--runtime` 执行，跨模块不要调。
- REQ-PORT-007（自原《模块API》移入，2026-10-02）：Web 面接口约定。客户端每次调用前读数据目录下的 `endpoint.json`
  （`%AppData%\HistoryVulcan\ModuleData\HistoryPortunus\endpoint.json`），连其 `port` 指定的回环端口，以其中 `accessToken` 作 Bearer；
  每次请求必须同时带 `Authorization: Bearer <accessToken>` 与 `X-HistoryVulcan-Client: Shell`，缺一返回 401；可选 `X-Session-Id`、`X-Client-Name` 标识会话。
  接口为 `GET /api/health`、`GET /api/commands`、`POST /api/command`（请求体 `{"text":"vulcan.module.list"}`）；根路径 `/` 不是健康检查。
  MCP 面不校验令牌，Cursor `mcp.json` 只写 `url=http://127.0.0.1:<mcp.port>/mcp`、不加 `headers.Authorization`。端口会变，一律用 `portunus.mcp.status` 问，不写死。
